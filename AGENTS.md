# Codex instructions — Arthur Santana portfolio

Read `docs/website-redesign.md` before proposing or implementing changes.

## Workflow
1. Inspect the existing repository, framework, routes, styles, assets, and content before changing anything.
2. Inventory all existing pages, roles, publications, presentations, research projects, and downloadable files. Do not silently remove or rewrite factual content.
3. Propose a phased plan and file-level change list; await approval before major implementation.
4. Work in small, reviewable increments. Keep the existing site functional throughout.
5. Prefer the existing stack unless there is a compelling, explained reason to change it. Keep GitHub Pages compatibility.
6. Never invent professional experience, project results, technologies, metrics, publications, or links. Mark missing information as TODO for review.
7. Treat client work as confidential. Do not publish proprietary code, screenshots, internal prompts, datasets, client identities, or architecture. The Multi-LLM Collaboration Framework is NDA-protected.
8. Ensure responsive layouts, semantic HTML, keyboard access, accessible contrast, reduced-motion support, and SEO metadata.
9. Implement light/dark themes with a visible toggle, system-preference default, and persistent user choice when feasible.
10. Validate builds, links, navigation, and layout before presenting changes. Summarize what changed and what remains to be reviewed.

## Editorial rules
- Preserve the complete academic archive and detailed professional experience.
- Distinguish implemented work from prototypes, designs, and proposed ideas.
- Do not claim performance gains or production deployment without verified evidence.
- Avoid generic AI stock imagery, exaggerated marketing copy, and flashy effects.
- Use concise, credible English suitable for technical recruiters and researchers.
